только кандидатов Facebook и Telegram. Изменение 12.09.2026 (каналы Telegram с

Owner-проект: Rent Searcher. Исполнено сессией Claude (основной инженер) по

## Зачем

Компьютер владельца ночью выключен, а суточный прогон шёл только на нём
(планировщик Windows, 09:00 и 21:00, с догоном пропущенного). Сайт обновлялся,
лишь когда компьютер включён.

Selectel отпадает сразу по трём пунктам. К тому же это общий клиентский продакшн,
где сборки запрещены правилами (`AI_CONTEXT/INFRASTRUCTURE/SERVERS.md`), а
прогон по сути и есть сборка сайта.

Риск Netcup — теснота: 1 vCPU, 967 МБ памяти, свободно ~430 МБ, подкачка 2 ГБ,
давление на память 0. На нём VPN владельца (Xray за nginx stream на 443) и сайты
apart/book/softapk.sunarrow.ru и sunarrow.ru. Пик памяти прогона измерен
локально по счётчику Windows PeakWorkingSetSize: `rebuild_final.py` 182 МБ,
`build_leaflet_data.py` 108 МБ, `build_pins_step2_geocode.py` 61 МБ,
`build_pins_step3_project.py` 57 МБ. Шаги идут по очереди.

## Что где идёт

- **Сервер:** Chợ Tốt, dotproperty, hoppler, каналы Telegram с заведением
  шаблонных постов (с 12.09.2026), обслуживание (снятые, чистка по возрасту,
  курсы, координаты), карта, сборка, публикация (git push).
- **ПК владельца** (`run_pipeline.py --candidates-only`): группы Facebook — только
  там, потому что программа ходит под личным аккаунтом владельца, а вход с адреса
  дата-центра — типичный повод для проверки личности или блокировки; и кандидаты
  Telegram для ручного разбора — посты свободным текстом, которые программа не
  заводит. Ничего не публикует и по шаблонам не заводит.

## Что создано на Netcup

- системный пользователь `rentsearcher` (uid 995), shell `/usr/sbin/nologin`,
  домашний каталог `/opt/rentsearcher` (права 750);
- `/opt/rentsearcher/app` — клон `Tottorisun/RentSearcherViet`;
- `/opt/rentsearcher/.ssh/id_ed25519` — ключ этого сервера для деплоя
  (`SHA256:5bYfgPlXy47oEmR0xj9ylInDfHScY39A968VLzojwro`), права 600;
  `known_hosts` — ключ github.com, отпечаток сверен с опубликованным GitHub;
- `/opt/rentsearcher/.gelios/token` — токен бота оповещений, права 600,
  перенесён с ПК через stdin, нигде не напечатан;
- `/opt/rentsearcher/pipeline.env` — `GELIOS_TOKEN_FILE`, `GELIOS_CHAT_ID`
  (права 640, root:rentsearcher);
- `PIPELINE_TIMEOUT_SCALE=2` в том же файле — множитель пределов шагов;
- `/etc/systemd/system/rentsearcher-pipeline.service` и `.timer` — копии из
  `server/` репозитория, таймер включён;
- на GitHub — deploy key «Netcup rentsearcher pipeline (write)», id 162986509,
  только для репозитория RentSearcherViet.

Ничего не изменено в nginx, Xray, UFW, SSH, DNS, чужих каталогах и службах.

## Пределы службы

`MemoryHigh=300M`, `MemoryMax=400M`, `MemorySwapMax=200M`, `CPUQuota=60%`,

когда-нибудь разрастётся, ядро остановит его, а не Xray.

## Изменение 12.09.2026: Telegram на сервере

**Зачем.** Строки из Telegram заводила только сессия на ПК, и ночью, пока ПК
выключен, Telegram на сайте не пополнялся. Большую часть постов пишут шесть
агентств по своим шаблонам; такие посты теперь заводит программа
`ingest_telegram.py` (правила — в её заголовке), остальные остаются кандидатами
для сессии. t.me с Netcup открывается (таблица выше), и Telegram-шаг уже шёл
на нём в пробном прогоне 11.09: 131 с при пределе 900.

**Что изменено — только в репозитории, на сервере руками ничего:**
- `server/run_on_server.sh`: `--publish --no-fb --no-tg` → `--publish --no-fb`;
- `run_pipeline.py`: после «Telegram: каналы» — шаг «Telegram: заведение по
  шаблонам» (`ingest_telegram.py --write --insert`), не фатальный; в режиме
  `--candidates-only` (ПК) его нет;
- новые файлы в репозитории: `ingest_telegram.py`; `osm_streets_da-nang.json`
  (выгрузка именованных улиц Дананга из OpenStreetMap через Overpass, 300 КБ,
  ODbL; обновляется `ingest_telegram.py --refresh-osm`); `telegram_ingest_state.json`
  (номера каталога и хэши текстов заведённых постов — чтобы перепост не
  завёлся дважды);
- комментарий и `Description` в `server/rentsearcher-pipeline.service`.
  Установленная копия юнита в `/etc/systemd/system` не переустанавливалась:
  отличается только подписью, запуск идёт через `run_on_server.sh` из
  репозитория.

**Когда вступает в силу.** Со второго прогона после пуша: оболочка читает
`run_on_server.sh` целиком до `git reset`, а reset кладёт новый файл рядом, не
трогая открытый. Прогон 12.09 05:00 по Вьетнаму идёт ещё без Telegram, первый
с Telegram — 12.09 17:00.

**Проверка до выкладки.** На исходных текстах всех 60 заведённых вручную
телеграм-строк сайта (посты прочитаны заново с t.me): 48 — те же район, тип,
цена, валюта и площадь; 10 — программа строже и пропускает (одна строка
прецедента вместо двух, «назван только прежний район», вероятный повтор);
**другого района — ни одного**. На 53 текущих кандидатах: заводится один новый
пост, остальные — уже на сайте, отсеяны теми же правилами, что и вручную, или
не по шаблону.

**Ресурсы.** Сбор каналов — 131 с (замер 11.09); заведение — секунды, первый
прогон дополнительно читает до 60 страниц t.me, чтобы запомнить уже заведённые
посты. Память — как у остальных шагов, они идут по очереди.

**Откат.** Вернуть `--no-tg` в `server/run_on_server.sh` и запушить: вступит в
силу через прогон по той же причине. Немедленно — `systemctl stop
rentsearcher-pipeline.service` на время текущего прогона.

**Evidence первого серверного прогона с Telegram (12.09.2026, 17:05-17:45 по
Вьетнаму, 40 минут, код возврата 0):** 16 шагов из 16, ни одного упавшего.
Шаг «Telegram: каналы» собрал 68 кандидатов; шаг «Telegram: заведение по
шаблонам» завёл 4 строки сам (id 2000629-2000632: улицы Mỹ Khê 1 и Lê Thiệt
по OSM, Son Thuy по прежнему району Ngũ Hành Sơn, ЖК CCU01 по прецеденту);
шаг «обслуживание: снятые в Telegram» проверил 60 постов -- живы все.
Опубликован `c6a5f18`, на сайте 3317 объявлений (утром было 2906).

## Откат

```sh
systemctl disable --now rentsearcher-pipeline.timer
rm -f /etc/systemd/system/rentsearcher-pipeline.service /etc/systemd/system/rentsearcher-pipeline.timer
systemctl daemon-reload
userdel -r rentsearcher          # удаляет /opt/rentsearcher целиком
gh repo deploy-key delete <id> --repo Tottorisun/RentSearcherViet
```
На ПК вернуть `run_daily_program.ps1` к `run_pipeline.py --publish`.
